# UI/디자인 반복 작업

이 프로젝트는 Vite + React + TypeScript + Tailwind v4 구조이고, 색상/타이포는 CSS 커스텀
프로퍼티로 토큰화되어 있다. 디자인을 고칠 때는 임의의 색을 하드코딩하지 말고 아래 규칙을 따른다.

## 1. 색상은 토큰으로

`src/index.css`의 `:root`(라이트)와 `html.dark`(다크)에 색이 쌍으로 정의되어 있다:

| 토큰 | 용도 |
| --- | --- |
| `--bg`, `--bg2`, `--bg3` | 배경 (기본/서브/카드) |
| `--txt` | 본문 텍스트 |
| `--muted`, `--subtle` | 보조 텍스트 |
| `--bdr` | 테두리 |
| `--hover` | 호버 강조 |
| `--accent`, `--accent2` | 포인트 색 |

새 UI를 만들 때 임의의 hex 값 대신 이 토큰(`var(--accent)` 등)을 쓴다. 새 토큰이 꼭
필요하면 라이트/다크 양쪽에 짝을 맞춰 추가한다 — 한쪽만 추가하면 다크모드에서 깨진다.

## 2. 컴포넌트 구조

- 섹션 단위 컴포넌트는 `src/components/sections/`에 있다 (Intro, Work, Research,
  Experience, Publications, Stack, Writing, Contact) — 새 섹션을 추가할 때 이 폴더의
  기존 컴포넌트 하나를 열어 구조(FadeIn 래핑, 섹션 제목 스타일 등)를 그대로 따른다
- 공통 UI는 `src/components/` 루트(`FadeIn`, `Header`, `Footer`)
- 애니메이션은 `framer-motion` 사용 중 — 기존 `FadeIn.tsx` 패턴을 재사용

## 3. 반응형

Tailwind 유틸리티 클래스로 브레이크포인트 대응한다. 사이드 여백은 최소한으로도
16px 이상 남기고, 데스크톱 전용 레이아웃(다단 그리드 등)은 모바일에서 1열로
접히게 확인한다.

## 4. 다크모드 확인

`html.dark` 클래스 토글로 다크모드가 적용된다. 새 색을 추가하거나 배경/텍스트를
바꿨으면 라이트/다크 양쪽에서 대비가 유지되는지 확인한다 — 토큰만 썼다면 대부분
자동으로 해결된다.

## 5. 심미적 판단이 필요할 때

색 조합, 타이포그래피 스케일, 레이아웃 리듬처럼 "정답이 없는" 디자인 판단이 필요하면
`frontend-design` 스킬을 함께 참고한다 — 이 스킬은 이 프로젝트의 컨벤션(토큰, 폴더
구조)을, `frontend-design`은 일반적인 심미적 방향을 담당한다.

## 6. 변경 후

디자인 변경도 `npm run build`로 타입 에러가 없는지 확인한 뒤 `commit-and-push` 스킬로
커밋한다. 시각적 확인이 필요하면 `run` 스킬로 로컬 서버를 띄워 직접 본다.
